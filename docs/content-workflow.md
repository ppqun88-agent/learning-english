# 文本制作工作流

> 后续更新：本文件保留最初归档讨论；资源整合状态与当前可执行步骤见 [执行计划](execution-plan.md) 和 [整合说明](resource-integration.md)。文中“未复制/未实现”描述的是归档时点，不代表最新交付。

状态：拟采用的处理流程，尚未批量执行。音频暂不纳入本阶段。

## 1. 明确目标词集

选定来源版本、集合范围、英美变体处理和计数单位。保存目标清单及选择说明，避免后续因来源更新导致覆盖分母变化。

不根据“约 5,000 词”的讨论数字直接截断词表。来源情况见[词库说明](vocabulary-sources.md)。

## 2. 清理教学目标

保留原始记录，另行标记适合当前内容的词性、常用义项和必要的搭配。对可疑释义、发音或分级先列为待核对，不将未经审查的解释写入正式材料。

多义词的其他义项可留待后续，不强制在一篇对话中塞入。

## 3. 按关联组织情景

从能够自然共同使用的词出发，构建具体沟通任务，例如询问情况、安排活动或处理问题。主题只是组织方式，不预设场景总量或每篇词数。

若内容显得生硬，优先调整词组归属或拆分情节，不为凑覆盖率牺牲自然度。自然重复允许出现，不设置跨场景最低重复次数。

## 4. 起草文本

每份内容建议包含：

- 稳定的内容 ID、标题、情景和沟通目标。
- 目标词 ID，以及本文使用的词性和义项。
- 带说话人和句子 ID 的英文对话。
- 中文理解说明与重点用法，具体形式待样稿确认。
- 来源词表版本、文本版本和处理状态。

以上是便于接续的最小信息建议，不代表已确定最终 JSON schema。先通过样稿验证，再锁定结构。

## 5. 分开检查覆盖与质量

自动检查适合处理：目标 ID 是否存在、文件结构是否完整、目标词是否遗漏、出现位置能否定位、同一内容 ID 是否重复。

语义检查处理：词性和义项是否对应、搭配是否自然、对话是否连贯、背景是否合理、中文解释是否准确、是否引入过多非目标难词。

词形匹配应记录证据位置。匹配到文本后仍需语义确认，不把子串命中或同形不同义误算为完成。

## 6. 修订与归档

发现漏词先判断它是否适合当前情景，再决定补充或重新分组。不要求每词跨场景反复出现，也不盲目增加场景来满足配额。

保存文本和检查结果，明确 `草稿 / 待审 / 已审` 等状态。只有核对过的有效用法计入覆盖。记录待处理项与原因，不把失败或待审项隐藏在总数里。

## 7. 学习使用

固定材料可反复阅读、理解和回听。若后续加入接话、复述或回忆练习，可优先复用已有内容。个人学习记录与公开内容分开管理，不进入本公开仓库。

内容覆盖目标与学习效果目标分别检查：前者看词集及用法，后者需要实际理解或表达证据，不能用播放次数代替。

## 8. 后续音频衔接

用户已有本地音频资源。当前只建议保留稳定的内容 ID 和句子 ID，方便未来建立文本与音频映射；尚未确定引擎、声音、音频粒度、文件格式或路径，不生成音频占位成果。

## 本阶段验收边界

本次建档只验收文档完整、链接正确、决定与建议区分清晰。上述流程尚未运行，不宣称目标词已覆盖、课程已生成或语义审校已完成。
