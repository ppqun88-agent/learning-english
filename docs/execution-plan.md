# 从词库资源到可靠情景对话的执行计划

更新日期：2026-10-22。终点是经过逐项核对、可追溯且可重复检查的情景对话文本，不是仅仅生成包含目标词的句子。本次交付资源接入与确定性检查基础，以及后续可逐阶段执行的计划；不宣称已完成全量对话生成或语义审校。

## 当前边界与执行原则

- 本次实现范围：固定来源、资源导入、候选目标输出、对话结构与形式覆盖检查、测试。后续课程目标审批、情景分配、起草、独立语义审校和全量冻结仍待执行。
- 默认候选集是 Oxford UK/US 标签并集的 5,062 个索引键。这是可复现的暂定工作集，不是已经批准的最终学习范围；也不是 5,062 个义项或词性记录。
- 原始词性与 CEFR 对应关系保留为候选记录。相同拼写下的多个词性、等级或义项不能仅凭词形合并为一个已完成教学目标。
- 情景数量随自然关联和沟通需要形成，不设固定总量、每篇目标词配额或跨情景最低复现次数。自然重复允许保留。
- 起草和审校优先人工配合现有可用模型，不配置付费 API，不开展新应用或音频服务开发。音频已有本地资源，留待文本稳定后接续。
- `build/` 为默认本地生成目录并由 Git 忽略。局部试验、候选词表和未经许可的第三方内容不随代码推送。

## 可直接运行的入口

以下命令在 `learning-english` 仓库根目录运行，要求 Python 3 与已准备好的相邻来源目录 `../wordlists-source`。来源必须对应固定版本 `3043da14627ed3c6168b598479bc110ce6b34736`；不能通过修改清单绕过不一致。

```bash
python3 tools/pipeline.py import --source-dir ../wordlists-source
python3 -m unittest discover -s tests -v
```

导入读取来源清单并验证文件校验值，再生成本地 `build/targets.jsonl` 等资源。具体输出与统计以导入报告为准。ECDICT 释义可作为查词参考，但原始释义不是已经清洗或审定的教学解释。

已有对话文件后，可运行以下入口；将 `path` 替换为单个对话 JSON 文件。当前不接受目录，批量生产时逐文件执行并汇总结果。

```bash
python3 tools/pipeline.py validate --dialogues path
python3 tools/pipeline.py validate --dialogues path --targets build/targets.jsonl
```

`--targets` 默认是 `build/targets.jsonl`，两种写法均核对候选清单中的精确 ID 关联。审核后使用其他目标文件时必须显式指定，避免校验了错误版本。上述命令不负责生成情景、批准义项或判断语义。下文未列出命令的步骤由人工维护记录，不能理解为已有自动化功能。

## 第一阶段 复现来源并验收资源接入

**状态：已实跑导入并通过 9 项测试；得到 5,062 个词形、6,187 条源目标记录，64 个词形缺音标。义项仍全部待审。**

输入：固定版本的 `wordlists`、本仓库来源清单与许可说明。

执行：

1. 运行导入与单元测试。任何来源校验失败均停止导入，先核对文件与版本，不静默使用最新版本。
2. 对照输出报告分别记录索引键数、候选目标记录数和缺少音标的词形数量。5,062 只用于核对 Oxford 标签索引键并集，不能充当原始 POS 记录数。
3. 核查大小写、多词表达、英美变体、多词性和多等级代表记录；确保保留来源信息，目标 ID 可在同一输入下稳定重建。
4. 每个源词性与 CEFR 组合导出为候选目标，保留词汇参考关联，`sense_status` 初始为 `pending`。没有明确义项的记录不得自动变成已审核目标。
5. 核对公开文件的来源和许可：按来源声明复用 MIT ECDICT 释义并保留署名；Oxford 原始词表、PDF 及派生完整内容不在本次公开仓库重新分发。来源许可存疑的内容只保留引用与本地处理方式。

输出：本地候选目标、资源引用、导入统计及可重跑的工具和测试；公开仓库保存有许可依据的资源、代码和说明。

通过条件：校验与测试通过；计数口径一致；没有把候选记录当作已审义项；没有越过许可边界。失败项保留原因，不能以“导入完成”替代许可或语义验收。

## 第二阶段 批准范围并整理词性和义项

**状态：待执行，是正式课程生产的前置条件。**

输入：`build/targets.jsonl`、参考释义和来源记录。

执行：

1. 提交默认候选并集供范围确认，写清英美变体处理、计数单位、保留与排除规则。不得为了凑 5,000 任意删词。
2. 按稳定 `target_id` 建立本地审核台账，逐项明确当前要教的词性、具体常用义项、必要搭配、认可词形和依据。参考释义有歧义时查证，不直接复制所有释义。
3. 原始导入文件保持可重建；批准内容另存审核台账，不靠手改源数据掩盖问题。导入的 `approved_forms` 初始只含原词形；人工依据审核台账制作独立本地 `build/approved-targets.jsonl`，保留全部稳定 ID 和来源字段，并明确填入批准的 `approved_forms`。这是后续手工整理步骤，当前没有自动投影命令。校验时使用 `--targets build/approved-targets.jsonl`，不修改原始来源或原始导入档。若一个候选项需要拆成多个教学义项，记录教学子项与原 `target_id` 的映射，先约定版本化 ID 规则，再扩展检查器。
4. 对每项使用明确状态：待审、批准纳入、暂缓、排除。暂缓和排除必须写原因、依据及范围版本，不能在统计时悄悄消失。

输出：本地范围决议与词义审核台账，包含范围版本、目标 ID、词性、义项、词形、审核人和依据。此台账是后续生产规格，不是本次自动导入已经生成的最终课程目标。

通过条件：首批全部目标有清楚的语义边界与审核记录；最终全量制作前，整个冻结范围有可追溯决议。先批准小范围试做不等于批准整个并集。

## 第三阶段 分配候选情景

**状态：待第二阶段首批目标批准后执行。**

输入：已批准的小范围教学目标。

执行：

1. 先按现实沟通任务组织词群，如确认安排、比较选择、说明问题；每个情景说明参与者、地点、双方诉求及对话如何结束。
2. 建立本地分配台账，记录 `scene_id`、沟通任务、目标 ID、预期词性义项、安排理由与难点。每个纳入目标必须有主归属或未分配原因，重复归属只在自然需要时保留。
3. 将难以自然放入的目标移入剩余项清单；允许拆分场景、改任务或另建情景，不要求每篇篇幅或词量一致。
4. 先挑能检验规则的代表性场景试做，覆盖常见多义词、词形变化、多词表达与大小写敏感词等风险；不以固定场景数量代替代表性。

输出：候选情景分配表、试做清单、未分配目标清单。

通过条件：任务本身合理，目标共现有自然理由；所有首批目标去向可查；没有为了覆盖率硬塞生僻或不相干用法。

## 第四阶段 起草小批对话并锁定样稿规范

**状态：待执行，不是已实现的一键生成服务。**

输入：候选情景、已批准的词性义项和词形。

执行：

1. 人工或现有可用模型起草英文对话，不调用未批准的付费服务。提示中提供沟通目标、教学义项与限制，明确不必为凑数量拖长文本。
2. 保存稳定对话 ID、句子 ID、说话人及文本，定位每个目标的具体证据句。需要中文理解说明时另列内容并纳入同等审校，不将未确认的解释格式设为全量标准。
3. 每篇标注起草者、版本、所用目标范围版本。单独记录自然度、难度、人物数量、篇幅、英美用语和中文说明的样稿反馈。
4. 样稿获认可后再定生产规范与下一批规模；批次以能完整审完为界，不预承诺数量或日期。

输出：本地试稿与样稿反馈，状态为草稿或待审，不标记为已覆盖。

通过条件：格式可检查，情景任务完整，目标证据可定位，样稿规范得到确认；词形检查通过只是进入审校的条件。

### 对话文件与生产记录约定

对话按以下结构保存；前三项用于当前形式检查，包含非空 `speaker` 等结构要求；`reviews` 是后续生产约定，不代表检查器已经强制验证审核字段：

- `id`：稳定对话 ID。
- `targets`：目标数组。每项含 `target_id`、`lemma`、经人工认可的 `forms` 数组、证据句 `sentence_ids` 数组。
- `sentences`：句子数组。每项含 `id`、`speaker`、`text`。
- `reviews`：生产阶段建议保存的审核数组；当前验证器忽略它，不验证其存在或内容。每项含 `target_id`、`reviewer`、`status`（`accepted` 或 `rejected`）、`rationale`。

目标 ID 从实际导入文件选取，不手工猜测或新编一个看似有效的 ID。审核理由应指出证据句，并解释该处如何满足已批准词性、义项和搭配；只写“正确”不能作为正式审核依据。更详细的场景元数据、目标义项台账、修改历史和整篇质量记录可另行保存；当前检查器不自动审定这些生产规格。

## 第五阶段 分离形式检查与独立语义审校

**状态：形式检查属于本次实现；真实审校待文本产生后执行。**

输入：待审对话、候选目标文件、批准目标台账、样稿规范。

执行顺序：

1. 用指定当前目标文件的验证命令（未批准变形时为 `--targets build/targets.jsonl`，批准后为 `--targets build/approved-targets.jsonl`）检查结构、重复 ID、目标 ID 精确关联、句子引用和证据词形。边界匹配不能把 `art` 在 `party` 中的子串当命中；大小写敏感目标不能仅因全部转小写而通过。
2. `forms` 必须来自人工认可的用法，不自动把所有词形或近义词当作覆盖。对多词表达、屈折变化、大小写和同形异义分别核查。
3. 由独立于该稿起草步骤的审校者阅读目标义项与完整上下文，逐目标检查词性、义项、搭配和语用是否正确，记录真实 `reviewer`、接受或拒绝、证据句及理由。可用独立模型审查辅助，但应保留工具或模型身份；同一生成结果不能自动给自己盖章。
4. 对整篇另查连贯性、人物动机、真实可用性、难度、解释准确性和不必要的非目标难词。疑难项须人工或可靠语言资料复核，分歧未解决保持待审。
5. 复跑形式检查，输出两种独立结果：形式命中；经审校接受的用法。不能将填写 `accepted` 当作程序已经证明语义正确，当前检查器忽略 `reviews`，既不验证审核记录内容，也不验证审校者判断的真实性。

输出：形式检查结果、逐目标审核记录、整篇质量意见和待修改项。

通过条件：没有结构与引用错误；每个计入有效覆盖的目标都有具体语义依据；整篇不存在未解决的质量问题。审校缺席、证据不足或意见冲突时，不得以“全部形式匹配”结案。

## 第六阶段 修订并清理剩余目标

**状态：待第五阶段产生反馈后循环执行。**

输入：拒绝项、未分配项、缺少证据项及全篇意见。

执行：

1. 按目标 ID 分类：缺失、词性或义项错误、搭配不自然、情景不适合、参考资料不足、范围待定。
2. 适合原情景的做最小必要修订；不适合的重新分配，不能为了保留原场景而扭曲表达。词义或范围变化回到第二阶段重新批准。
3. 文本或目标改变后，旧审核对该版本失效，重新做形式检查与受影响语义审核；不能沿用与新文本不符的证据句。
4. 按冻结范围核对每个目标的最终去向。分别报告候选索引键数、批准教学项数、形式命中数、已接受用法数、未解决数；跨情景重复只计一次目标完成。

输出：修订版本、复审结果、剩余目标清单及处置理由。

通过条件：批准范围内每个目标均有至少一处经过审核的有效用法。尚有剩余项时可发布明确标为阶段性成果的批次，但不得声称全量完成。缩减范围必须形成显式的新决议，不能通过改分母制造完成率。

## 第七阶段 冻结可靠文本并准备后续接续

**状态：待全部范围内目标与整篇文本通过审核后执行。**

输入：已审文本、目标范围决议、审核证据、修订记录与许可核查结果。

冻结门槛：

1. 固定来源 SHA、目标范围版本、数据契约版本、工具版本、文本版本和审校记录版本。
2. 最后一次重跑单元测试和全部对话验证，保存命令、结果与输入文件校验值；记录是否仍存在工具未覆盖的人工检查。
3. 对最终对话、目标台账和审校记录生成 SHA-256 清单，确保后续能确认文本没有在审核后变动。生成清单属于届时执行步骤，不暗示当前已有全量发布命令。
4. 所有范围内目标有已接受证据，所有整篇问题已解决，未解决语义项为零；没有伪造审校者、证据或模型审查结果。
5. 单独核对发布许可与隐私。可公开的原创对话和有许可依据的材料才提交；含第三方完整词表、未授权摘录或私人学习记录的本地文件继续留在忽略目录。不能因为文件由程序生成就视为可公开。

输出：版本固定的可靠情景对话文本、对应审核与验证记录、校验清单、必要的阅读和接续说明。确认许可与授权后再将适宜公开的成果纳入版本控制。

最终验收表述应说明冻结的目标范围及有效用法覆盖，不宣称覆盖全部英语词义或证明个人已掌握。保留内容 ID 和句子 ID 供未来本地音频映射；此时仍不生成音频占位文件，也不预设音频供应商。

## 每次接续的最短操作清单

1. 读本计划和[决策记录](decisions.md)，检查上次输出及阻塞项。
2. 从首个未通过门槛的阶段继续，不跳过义项审批或审校。
3. 更新该阶段状态、输出位置、实际命令与结果、未检查部分以及下一步；失败原因须具体到目标或文件。
4. 仅当当前阶段验收通过，才进入依赖它的阶段。对外汇报清楚区分已实现工具、已处理内容与仍待执行的计划。
